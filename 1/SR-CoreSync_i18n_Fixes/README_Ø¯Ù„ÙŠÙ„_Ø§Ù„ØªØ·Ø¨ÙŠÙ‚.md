## 3) طريقة التطبيق

### الطريقة أ — عبر git (موصى بها للمستودع الرئيسي)
```bash
cd <نسخة-المستودع>
git checkout main
git am 0001-fix-i18n-complete-multilingual-coverage.patch
```
الرقعة تُطبَّق نظيفاً على الشجرة الأب `6e6ff88` (تم التحقق بـ `git apply --check`).

### الطريقة ب — نسخ مباشر (للمجلدات على الهاردديسك / الاستضافة)
انسخ كل ملف من `full_files/` إلى نفس المسار في موقعك:
- `js/sr-geo-lang.js` → `js/sr-geo-lang.js` (نفس المسار)
- `bg/index.html` → `bg/index.html` … وهكذا لكل لغة

> ⚠️ إذا كان الهاردديسك يحتوي نسخاً قديمة مُعدَّلة يدوياً فستُستبدل بهذه النسخ الموحّدة.

### التحقق بعد التطبيق
```bash
node --check js/sr-geo-lang.js          # يجب أن يمر بدون أخطاء
# أي صفحة لغة: لا ينبغي أن تجد عناوين إنجليزية مثل
#  "Frequently Asked Questions" أو "Predictable, Transparent Pricing"
```

## 5) إجابة سؤال المستودع الرئيسي / الهاردديسك

**لا، لا أنفّذ التحديثات مباشرة على المستودع الرئيسي على GitHub ولا على مجلدات هاردديسكك.**

- أعمل داخل بيئة معزولة (Sandbox) وعلى نسخة محلية مستنسخة من المستودع فقط.
- **لا أملك بيانات دخول (Credentials) إلى حساب GitHub**، ولا أستطيع الوصول إلى القرص الصلب/الملفات المحلية عندك.
- كل التغييرات تُسلَّم لك كـ: رقع `git am` + ملفات كاملة للنسخ المباشر — **وأنت** تطبّقها على: (أ) المستودع الرئيسي، (ب) نسخ الهاردديسك، (ج) الاستضافة/Cloudflare Pages.
- إن أردت التطبيق الآلي على GitHub لاحقاً: يمكن ذلك عبر **Deploy Key أو Personal Access Token بصلاحيات محدودة** توفّره أنت عمداً — أو الأبسط: طبّق الرقعة محلياً ثم `git push` من جهازك.
