القسم 1
الصورة الكبيرة: أين التحديثات الآن؟

قبل أي خطوة، من المهم أن تفهم أين توجد التحديثات حالياً ولماذا لا تصل إلى GitHub أو جهازك تلقائياً:

التحديثات أُنجزت داخل بيئة عمل معزولة خاصة بمساعد الذكاء الاصطناعي، وجرى تجميعها في ملفي ZIP موجودَين في هذه المحادثة. هذه البيئة المعزولة لا تملك كلمة سر حسابك في GitHub، ولا تستطيع اللمس أو الوصول إلى الهاردديسك في جهازك — لذلك لا يمكن رفع الملفات تلقائياً إلى أي منهما. أنت الوحيد القادر على نقل التحديثات من المحادثة إلى أماكنها، والدليل كله يدور حول هذه الخطوات الثلاث البسيطة:

1

كملفي ZIP قابلين للتنزيل
2
أنت تنزّلهما إلى جهازك
زر التنزيل بجانب كل ملف
3
تضع الملفات في مكانها الصحيح
الهاردديسك أو GitHub أو الاستضافة
بمعنى آخر: أنا (المساعد) جهّزت كل شيء وحزمته وتحققت منه، لكن «آخر كيلومتر» — عملية الرفع الفعلية — تقع على عاتقك لأن الحسابات والأجهزة ملكك وحدك. الأخبار الجيدة: العملية كلها لا تتجاوز نسخ ولصق أو سحب وإفلات، وأي طريقة من الطرق الثلاث في الأقسام التالية تكفي.

تناسب: جهازك الشخصي، الاستضافة، لوحة ملفات السيرفر
الأسرع من كل هذا — نقرة واحدة: داخل كل حزمة يوجد ملف تشغيل جاهز باسم apply_updates.bat (لويندوز) و apply_updates.sh (لماك ولينكس). شغّل الملف وأشر إلى مجلد مشروعك، فيضع كل الملفات في أماكنها الصحيحة تلقائياً، وإن كان مجلدك مستودع git فسيحفظ التغييرات ويدفعها إلى GitHub بعد أن تعطي موافقتك في نافذة المتصفح التي ستفتح لك.
1
فك الضغط عن الملفين. اضغط بزر الفأرة الأيمن على كل ملف ZIP واختر «استخراج الكل» — ستحصل على مجلدين: SR-CoreSync_P0_Patches و SR-CoreSync_i18n_Fixes.

القسم 4
الطريقة ب: تحديث المستودع على GitHub من المتصفح
بدون برامج أو أوامر
الرفع من موقع GitHub نفسه بالسحب والإفلات
تناسب: من لا يستخدم git أصلاً

GitHub يتيح رفع الملفات من المتصفح مباشرة. اتبع الخطوات التالية بالترتيب:

1
افتح المستودع في المتصفح وسجّل الدخول بحسابك: github.com/Salim-Grav/SR-CoreSync---For-Intelgent-Solutions
2
لملفات الجذر: من الصفحة الرئيسية للمستودع اضغط Add file ← Upload files، ثم اسحب ملفات الجذر الثمانية من P0/full_files/ (المدرجة في جدول القسم 3) إلى منطقة الرفع.
3
لملفات المجلدات الفرعية: ادخل أولاً إلى المجلد المطلوب (مثلاً scripts) ثم اضغط Add file ← Upload files واسحب الملفين إليه، وكرر مع web ومجلدات اللغات. أو ببساطة: اسحب المجلد كاملاً من نافذة جهازك إلى صفحة الرفع وسيحفظ GitHub بنيته.
4
اكتب وصفاً قصيراً ثم اضغط Commit changes. مثلاً: «تطبيق ترقيع الأمان P0». كرر العملية نفسها لملفات حزمة الترجمة الـ 54 (يفضّل سحب مجلدات اللغات دفعة واحدة).
ملاحظة: هذه الطريقة أبطأ قليلاً لأنها يدوية، لكنها آمنة تماماً وتعطيك تحكماً كاملاً: ترى كل ملف قبل حفظه، ويمكنك في أي وقت الرجوع إلى نسخة سابقة من أي ملف عبر زر History في صفحة الملف.
القسم 5
الطريقة ج: عبر أوامر git (الأدق — للمستودع الرئيسي)
الموصى بها للمطورين
تطبيق الرقع بالترتيب ثم الرفع بضغطة واحدة
تناسب: من يعرف أساسيات git

الحزمتان تتضمنان رقع git جاهزة (.patch) حفظت بنية التعديلات الكاملة. هذه أسرع وأدق طريقة لتحديث المستودع الرئيسي، بشرط تطبيق الرقع بهذا الترتيب تحديداً:

# 1) نزّل نسخة جديدة من مستودعك
git clone https://github.com/Salim-Grav/SR-CoreSync---For-Intelgent-Solutions.git
cd SR-CoreSync---For-Intelgent-Solutions

# 2) طبّق رقع الأمان P0 الأربعة بالترتيب (من مجلد patches بعد فك الضغط)
git am /path/to/SR-CoreSync_P0_Patches/patches/0001-security-a1-add-sovereign-API-key-auth-layer-rate-li.patch
git am /path/to/SR-CoreSync_P0_Patches/patches/0002-security-a1-a3-a4-a8-enforce-auth-restrict-CORS-hard.patch
git am /path/to/SR-CoreSync_P0_Patches/patches/0003-security-p1-p5-whitelist-build-context-defense-in-de.patch
git am /path/to/SR-CoreSync_P0_Patches/patches/0004-security-p2-p3-stop-committing-runtime-artifacts-his.patch

# 3) طبّق رقعة الترجمة الكاملة
git am /path/to/SR-CoreSync_i18n_Fixes/patches/0001-fix-i18n-complete-multilingual-coverage.patch

# 4) ارفع كل شيء إلى GitHub دفعة واحدة
git push origin main
مهم جداً: استبدل /path/to/ بالمجلد الحقيقي الذي فكّ فيه ضغط الحزم على جهازك. والتزم الترتيب: رقع P0 من 0001 إلى 0004 أولاً، ثم رقعة الترجمة — لأن رقعة الترجمة مبنية فوق نتيجة رقع الأمان، وتطبيقها قبلهما قد يسبب تعارضاً. إن ظهرت رسالة خطأ في أي رقعة، لا تُكمل: انسخ نص الرسالة وأرسله لي وسأحلها معك.
القسم 6
بعد التطبيق: كيف تتأكد أن كل شيء نجح؟

مهما اخترت طريقة، هناك اختباران سريعان يثبتان النجاح خلال دقائق:

اختبارطريقة التحقق والنتيجة المتوقعة
الترجمة تعمل افتح في المتصفح أي صفحة لغة من موقعك، مثل de/index.html أو fr/index.html أو tr/index.html. يجب أن تظهر الصفحة كاملة بلغتها — العناوين والفقرات والأسئلة الشائعة — دون أي فقرات إنجليزية متبقية. قبل الإصلاح كانت الفقرات إنجليزية في كل اللغات تقريباً.
الأمان يعمل من مجلد المشروع نفّذ: python3 scripts/generate_auth_keys.py لولادة مفاتيح API، ثم أعد تشغيل الخادم، ثم python3 smoke_test/p0_smoke_test.py — النتيجة المتوقعة 16 من 16 فحصاً ناجحاً.
سلوك مقصود لا تخف منه: بعد تطبيق ترقيع الأمان P0، الخادم الذي يعمل بدون مفاتيح API صالحة يرفض خدمة الطلبات ويجيب برمز 503. هذا ليس عطلاً بل حماية مقصودة (إغلاق آمن). المفتاح إلى العمل الطبيعي: ولّد المفاتيح بالأمر أعلاه وضبطها في ملف البيئة، والشرح الكامل موجود داخل ملف README_دليل_التطبيق.md المرفق في كل حزمة.
القسم 7
أسئلة سريعة وجوابها المباشر
هل رفعتَ أنت التحديثات إلى المستودع الرئيسي على GitHub؟
لا. لا أملك صلاحية الدخول إلى حسابك في GitHub ولا يمكنني الرفع باسمك، ولا أستطيع الوصول إلى أي جهاز. كل ما أنجزته موجود في ملفي ZIP هنا في المحادثة، والرفع النهائي يتم بيدك بإحدى الطرق الثلاث أعلاه.
وماذا عن «مجلدات الهارديسك» التي سألت عنها؟
أي نسخة من المشروع محفوظة خارج GitHub: على جهازك، أو على قرص خارجي، أو على السيرفر/الاستضافة. طبّق عليها الطريقة أ (النسخ المباشر) على كل نسخة على حدة. إن كان لديك مسار مجلد بعينه غير متأكد منه، أخبرني بمساره وسأحدد لك بدقة الملفات التي توضع فيه.
أي طريقة أنسب لي؟
لا تعرف git؟ اختر الطريقة أ لنسخ جهازك والاستضافة، والطريقة ب لتحديث GitHub. تعرف git أو لديك من يساعدك؟ الطريقة ج هي الأنظف لأنها تطبق التعديلات كاملة بمحتواها التاريخي وبرسالة وصف لكل رقعة.
هل يمكنني تطبيق حزمة الترجمة فقط دون حزمة الأمان؟
تقنياً نعم — ملفات الحزمتين لا تتصادم. لكن لا ننصح بذلك إطلاقاً: حزمة الأمان تغلق ثغرات حقيقية (24 نقطة وصول API كانت مكشوفة بلا مصادقة)، وتأجيلها يترك المشروع مكشوفاً. طبّق الأمان أولاً دائماً.
القسم 8
أي طريقة أختار؟ جدول القرار السريع

للخلاصة، هذا الجدول يجيب في سطر واحد عن سؤال «من أين أبدأ؟» حسب حالتك — ويمكنك دمج أكثر من طريقة معاً: مثلاً تطبيق الطريقة أ على نسخة جهازك والطريقة ج على المستودع في الوقت نفسه، فكلاهما يحتاج إلى التحديث:

الطريقةاخترها إذا كنت…ماذا تحصل عليه؟
أ — النسخ المباشر تريد النتيجة الأسرع دون أي أوامر، ولديك نسخة المشروع على جهازك أو على الاستضافة ملفات محدثة فوراً في مكانها، وتتحقق منها بفتح صفحات الموقع مباشرة
ب — الرفع من المتصفح لا تستخدم git، وتريد تحديث المستودع على GitHub بنفسك من المتصفح تعديلات محفوظة في المستودع، مع إمكانية التراجع عن أي ملف عبر History
ج — أوامر git تعرف أساسيات git أو تستطيع نسخ 8 أوامر ولصقها بالترتيب النتيجة الأدق: الرقع الكاملة بوصفها التاريخي، ثم رفع الجميع بضغطة git push واحدة

وسواء اخترت ما اخترت، لا تنسَ الخطوتين اللتين يغفل عنهما كثيرون: توليد مفاتيح API بعد ترقيع الأمان، ثم تشغيل اختبار الفحص السريع للتأكد — هما خط الحسم بين «طبّقت الملفات» و«التحديث يعمل فعلاً».

الخلاصة: خطتك في 6 خطوات
من هذه المحادثة إلى مستودع ونسخ محدّثة بالكامل — بهذا الترتيب بالضبط:
1
نزّل الحزمتين من هذه المحادثة إلى جهازك وفك الضغط عنهما.
2
خذ نسخة احتياطية سريعة من مشروعك الحالي قبل أي استبدال.
3
طبّق حزمة الأمان P0 أولاً — بالنسخ المباشر أو بالرقع حسب طريقتك.
4
طبّق حزمة الترجمة i18n — فتنعم الـ 26 لغة بمحتوى أصيل بلغتها.
5
ولّد مفاتيح API وأعد تشغيل الخادم حتى لا يبقى في وضع الإغلاق الآمن 503.
6
تحقق: افتح صفحات اللغات وشغّل اختبار الفحص السريع (16/16).
تذكير أخير: أنت وحدك من يملك مفاتيح الوصول إلى حسابك في GitHub وأجهزتك — وهذا سبب بقائك وحدك القادر على الرفع. إن تعثّرت في أي خطوة، أو ظهرت رسالة خطأ أثناء تطبيق الرقع، انسخها وأرسلها هنا وسأتولى حلها معك خطوة بخطوة.
